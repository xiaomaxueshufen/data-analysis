# 报告多样性协议（固定六段式）

本文件是给模型的思考辅助，目的是让每次分析报告在真实可信的前提下呈现不同的视角和视觉表达。**内容骨架固定为原版六段式**：核心发现 → 分析背景与目标 → 数据概况 → 深入分析 → 结论与建议 → 附录。多样性只发生在视觉、图表语法和叙事侧重，不改变章节顺序。

## 何时必须变化

- 同一会话内用户要求“再分析一次”“换个角度看看”“重新出一版”；
- 同一份数据被追问不同问题；
- 用户没有明确要求固定格式时，每次正式报告生成前。

同一会话内，两次报告的“完整变化组合”（主视角 × 视觉结构 × 图表语法 × 版式节奏）不得重复。事实数字必须与数据一致，但解读侧重、语言表达和视觉呈现每次都要不同。

## 变化维度一：分析主视角

| 视角 | 切入问题 | 适合场景 |
|---|---|---|
| decision | 用户要做什么决定，报告如何缩短决策路径 | 有明确业务动作 |
| mechanism | 哪些可观测变量与异动同步，哪些解释被排除 | 排查型问题 |
| structure | 结构变化还是组内变化，谁贡献了缺口 | 拆解型问题 |
| quality | 数据本身是否可信，哪些结论被质量门禁拦截 | 谨慎交付 |
| opportunity | 当前数据揭示哪些未被利用的机会 | 探索性问题 |
| falsification | 主动找反例：什么情况下这个结论不成立 | 高风险决策 |

每次运行选一个主视角、最多一个辅助视角。上次用过 Decision，这次至少换成 Mechanism 或 Falsification。

## 变化维度二：视觉结构

| 结构 | 允许的变化 |
|---|---|
| pyramid | 在六段式内强化“结论 → 证据 → 边界”的阅读节奏 |
| investigation | 深入分析章节按“现象 → 假设 → 检验 → 排除”组织 |
| contrast | 深入分析章节并列两种解释，用证据逐条裁决 |
| layered-disclosure | 首屏只放事实，图表与明细逐层展开 |
| storyline | 深入分析按时间线或决策链路推进 |

这些变化只能影响“深入分析”章节的内部组织方式，不得新增顶层章节或改变六段式顺序。

## 变化维度三：图表语法

| 语法 | 表达重点 |
|---|---|
| baseline-overlay | 当前值与基线对照 |
| decomposition | 缺口拆到维度、结构、组内 |
| flow | 漏斗、路径、阶段损失 |
| distribution | 分布、离散、离群点 |
| matrix | 多指标交叉，突出异常格子 |
| minimal-table | 不画图，用一张精简表格承载全部证据 |

图表只画能支持当前结论的内容。没有足够证据就不画归因图；必要时用 minimal-table 替代装饰性图表。

## 变化维度四：版式节奏

- dense-first：首屏高密度数字与结论，附录放方法；
- airy-narrative：大字号叙事，数字作为锚点穿插；
- card-based：每个发现一张证据卡，可独立阅读；
- longform：一条主线贯穿全文，图表服务叙事。

## 变化维度五：建议形态

- 下一步实验设计（需要什么样本和对照）；
- 补数清单（缺什么字段，补齐后能验证什么）；
- 决策树（什么条件下走 A，什么条件下走 B）；
- 反证清单（什么现象出现时当前解释应被推翻）；
- 监控口径（应该长期看哪几个指标，阈值如何设定）。

每次至少换一种建议形态，不重复上一次的清单结构。

## 运行清单

生成报告前，把本次选择写入运行目录（例如 `variation.json`），格式：

```json
{
  "primary_lens": "mechanism",
  "secondary_lens": "falsification",
  "visual_structure": "contrast",
  "chart_grammar": "decomposition",
  "layout_rhythm": "card-based",
  "recommendation_form": "decision-tree",
  "previous_signature": "decision/pyramid/baseline-overlay/dense-first/checklist",
  "diff_from_previous": "主视角从决策改为机制，叙事从金字塔改为对立解释裁决"
}
```

`diff_from_previous` 必须写清楚本次与上次的具体差异，不能只写“换了个角度”。
