# HTML 报告规范（原版六段式 + 现代视觉）

## 目标

保留 GitHub 原版报告的内容骨架：**结论先行、证据随后、下一步建议、附录留痕**。视觉与图表可以现代化，但不得改变这六段的信息层级。

## 固定页面骨架

1. **Masthead**：报告类型、标题、观察窗、主指标、质量状态和来源表。
2. **核心发现**：3–5 条编号结论，每条包含事实、证据 ID、限制和观测信号。
3. **分析背景与目标**：一段叙事说明业务问题、分析对象、受众和决策场景。
4. **数据概况**：数据来源、字段、样本、时间窗、质量状态和关键口径。
5. **深入分析**：按问题分节，每节一张主图 + 一段读图说明 + 证据表。
6. **结论与建议**：先给总体判断，再给下一步实验、补数或监控建议。
7. **附录：数据处理说明**：清洗、转换、假设、排除区和证据 ID 对账。

> 视觉模块（Fact rail、Decision grid、Detail table）只能嵌入上述六段内部，不得新增顶层章节或改变顺序。

## 视觉设计

- 以下色板与栅格是一套可用的无障碍基线，不是唯一主题；可在同一报告内替换为对比度足够的其他主题，但六段式内容骨架不得改变。
- 淡蓝色画布 `#eef6fb` 衬托白色报告页 `#ffffff`，报告页顶部使用一条低饱和蓝色边线。
- 正文深色 `#1f2428`，主色 `#4b9dcc`，负向 `#df6b72`，正向 `#4e9b83`，边界线 `#d7e8f2`。
- 优先使用边线、留白、编号和排版层级，不使用大面积渐变、装饰插画、重阴影或过多圆角卡片。
- 关键数字用 `font-variant-numeric: tabular-nums`；百分比、百分点和绝对量分开写。
- 桌面端图表占 8 列，读图栏占 3 列；窄屏退化为单列。
- 首屏不放长表，逐字段证据放在 `details` 折叠区。

## 图表选择

- 时间序列：观测值蓝线、基线红色虚线、日期标签和图注；用于定位，不自动证明原因。
- 漏斗：阶段规模条形图，旁边标阶段转化率；分母不确定时必须降低措辞。
- 贡献度：正向项、负向项和残差对账；没有可加总分组时不画贡献图。
- AB/因果：效应点、区间、主指标和护栏；没有合规检验时不画上线结论图。
- 分层：规模与价值/响应的排序或散点；没有动作前特征时不画策略分层图。

每张图必须在图注中说明指标、时间窗、基线、单位、样本和排除区。图表数量服从证据，不为了填版面而画图。

## 渐进式披露

- 首屏只展示能影响决策的 3–6 个发现。
- 第二层展示每个发现的图表、偏离、分母、对账项和证据 ID。
- 第三层展开质量旗标、字段级证据、假设、残差和完整来源。
- 后续分析路线不得写成“建议持续关注”，必须回答补什么、验证什么、影响什么决定。
- 视口进入时允许标题、事实栏、图表和路线轻量上移显现；`prefers-reduced-motion: reduce` 时必须关闭动画。
- 目录可以根据当前可见章节切换活动项，但不能改变报告口径或隐藏证据。

## 离线与可访问性

- HTML 自包含，不依赖 CDN、远程字体、远程图片或外部 JavaScript。
- 使用语义化 `main`、`header`、`section`、`nav`、`figure`、`table`、`details`。
- 提供跳转链接、图表 `aria-label`、表头 `scope` 和移动端布局。
- 不使用只能靠颜色表达的结论，质量排除同时用文字标识。
