# 零售电商行业分析模板

## 适用范围与识别信号

适用于线上零售、电商平台、O2O 零售、品牌商城、直播电商和有商品交易链路的业务。建议至少同时出现以下两类信号：订单/支付/退款 ID、用户 ID、商品或 SKU、访问/曝光/加购/下单事件、库存流水、发货/签收、营销活动或渠道成本。

仅有销售额或订单量时使用通用模板；不能据此补出转化率、毛利、复购或库存周转。

## 业务链路与统计对象

```text
曝光/访问 → 商品浏览 → 加购 → 下单 → 支付 → 发货 → 签收
                                        → 退款/退货/客诉
商品与库存：采购/入库 → 可售库存 → 出库/损耗 → 盘点
```

先明确分析实体是访客、用户、订单、订单行、SKU、包裹还是库存快照。一笔订单可以包含多个 SKU，订单状态和支付状态也可能不同；不能把订单行、支付流水或物流扫描行直接当订单数。漏斗只有在同一用户/订单 ID、事件时间和重复规则明确时才成立。

## KPI 词典与必要条件

| 指标 | 推荐定义 | 至少需要 | 禁止推断 |
|---|---|---|---|
| GMV | 约定窗口内已支付订单的商品成交金额；明确是否含运费、优惠、税和取消/退款前金额 | 订单/支付 ID、金额字段、支付状态、窗口 | GMV 不是确认收入，也不能与净收入混用 |
| 净销售额/实收 | 按财务口径扣除退款、折扣和税费后的金额 | 支付、退款、优惠、税和财务确认规则 | 只有 GMV 不能推断实收 |
| 支付订单数/支付用户数 | 去重支付订单或支付用户 | 订单 ID、用户 ID、支付状态 | 支付流水笔数不能代替订单数 |
| 客单价（AOV） | GMV 或净销售额 / 支付订单数，分子口径必须一致 | 金额、支付订单 ID | 未说明退款/优惠时不能跨期比较 |
| 访问—下单转化率 | 下单用户数 / 访问用户数（用户去重、窗口一致） | 用户级访问与下单事件 | 访问次数不能直接做分母 |
| 加购率 | 加购用户数 / 访问用户数，或加购次数 / 访问次数，二者分开命名 | 加购、访问事件和去重规则 | 不把加购次数当用户数 |
| 加购—支付转化率 | 发生加购且在窗口内支付的用户/订单 / 加购用户/订单 | 关联 ID、归因窗口、事件时间 | 不把不同窗口的加购与支付拼接 |
| 复购率 | 约定 cohort 在窗口内再次支付的用户数 / 进入 cohort 的支付用户数 | 用户 ID、支付时间、复购窗口 | 未说明 cohort 和窗口不能写“复购率” |
| 新客占比 | 首次支付用户数 / 支付用户数；首次支付需查历史 | 用户支付历史、用户 ID | 首次访问不等于新客 |
| UV 价值 | GMV 或净销售额 / 去重访问用户数 | 访问用户、金额、同一窗口 | 没有去重用户不能称 UV 价值 |
| 件单价/连带率 | 商品金额 / 销售件数；销售件数 / 支付订单数 | 订单行、数量、金额、取消/退款规则 | 订单行数不能代替销售件数 |
| SKU 动销率 | 有约定销量的 SKU 数 / 统计期在架 SKU 数 | 在架 SKU 快照、销售 SKU、口径 | 没有在架集合不能算动销率 |
| 缺货率 | 缺货事件或缺货时长 / 应售 SKU—时间集合 | 库存快照、可售规则、时间窗口 | 没有应售集合不能算缺货率 |
| 库存周转天数 | 平均库存成本 /（销售成本 / 天数），必须按成本口径 | 库存快照、销售成本、窗口 | 用库存金额 / GMV 代替周转天数 |
| 退款/退货率 | 完成退款/退货的订单数或金额 / 约定支付/签收分母 | 退款/退货状态、订单 ID、分母规则 | 退款申请或客诉不能直接当退货完成 |
| 履约时效 | 约定起点到签收的 P50/P90 时长 | 订单/包裹 ID、事件时间、时区、异常规则 | 只有日期不能声称小时级时效 |
| 妥投率 | 在观察窗内完成签收的包裹 / 应签收包裹 | 包裹 ID、签收状态、观察窗 | 未成熟包裹不能与完整窗口混比 |
| 客诉率 | 物流/商品客诉订单或工单 / 明确的订单或用户分母 | 工单类型、去重规则、分母 | 工单数不能直接与订单数比较 |
| 获客成本（CAC） | 获客相关营销、销售成本 / 新增付费用户数 | 成本科目、用户首付、归属规则 | 只有广告花费不能代表完整 CAC |
| 投入产出比（ROI） | 约定收入或增量收入 / 约定成本，写明是否含履约、人力和退款 | 收入、成本、归因/对照规则 | GMV / 广告费不自动是增量 ROI |
| 毛利额/毛利率 | 按成本会计口径计算的收入减商品、履约等成本 | 商品成本、履约成本、收入和分摊规则 | 缺少成本不能用行业毛利率补值 |

指标必须写清金额口径、时间窗口、订单/用户实体和分母。目标值来自用户确认的经营目标、合同或历史基线，不在模板中预置“健康阈值”。

## 必须通过的数据门禁

1. **订单链路 ID**：订单、用户、订单行、SKU 和包裹可关联并能稳定去重。
2. **状态与时间顺序**：下单、支付、发货、签收、退款/退货时间可排序；取消和部分退款有独立状态。
3. **金额对账**：商品金额、运费、优惠、税、支付、退款能按用户确认的财务规则闭合；退款不超过可退金额。
4. **漏斗分母**：访问、加购、下单、支付使用同一实体和窗口；跨端事件有统一用户/设备映射，否则分端报告。
5. **库存流水**：入库、出库、损耗、盘点和库存快照的口径一致；缺货与在架集合可重建。
6. **成本匹配**：商品、物流、营销和人力成本有科目、归属窗口和订单/SKU/渠道粒度；无法分摊时不算利润或 ROI。
7. **归因规则**：渠道和活动有曝光/点击、归因窗口、优惠成本和退款处理；无对照时不写增量。
8. **观察窗**：复购、退款、签收和留存使用成熟 cohort，末端未完成订单进入右删失区。
9. **分组可加总**：渠道、品类、地区和设备的分子分母能对账总量；不能把分组率简单平均。

## 典型分析主题与流程

### 1. GMV/净销售额增长拆解

先确定 GMV、净销售额和退款的财务口径，再按支付用户数、购买频次和客单价拆解；新客与老客、渠道与品类仅在用户/订单粒度可加总时做贡献。若缺少用户 ID，降级为订单数、金额和客单价趋势，不推断增长来自拉新或提频。

### 2. 转化漏斗诊断

重建“曝光/访问 → 浏览 → 加购 → 下单 → 支付”，报告每阶段分母、损失量和用户去重。按渠道、设备、新老客和活动分层，先排除埋点缺失、口径变更和窗口错配；没有共同分母时分别展示事件量。

### 3. 商品、品类与库存贡献

同时看销售规模、毛利、动销、缺货和周转，区分少数 SKU 的规模贡献与组内效率。补货或清仓建议必须以可售库存、在途、需求窗口和成本字段为基础，不能从销量单列推断库存风险。

### 4. 用户 cohort 与生命周期

以首次支付或指定业务事件建立 cohort，按成熟窗口计算复购、留存和价值；RFM 只作为描述性分层，分层边界要记录。没有历史支付或用户 ID 时，不计算复购率和 LTV。

### 5. 营销活动和渠道评估

对齐活动曝光、参与、成本、支付、退款和活动后复购。无随机对照时报告按归因模型的订单/收入及历史基线差异，不能将其写成增量效果；有对照时再估计增量及区间。

### 6. 退款、退货与客诉

按原因、SKU、供应商、仓库、物流商和时间批次对账，区分申请、审核、完成和争议。相关性用于排查候选机制，责任判定需要订单级事件和质检/物流证据。

## 行业叙事语言

- “GMV 相对同星期基线偏离 X；净销售额的变化还需按退款和优惠口径核对”；
- “转化下降集中在支付前阶段，数据支持优先核查该阶段，尚不能判定唯一原因”；
- “某品类贡献了整体变化的 X%，同时其订单规模和组内转化均发生变化”；
- “活动期按归因模型记录了 X 元订单额，未设置对照，不能称为增量”；
- “末端订单观察窗未完成，当前退款/妥投结果存在右删失”；
- “若补充成本、库存快照和用户历史，可进一步验证毛利、周转和复购”。

避免使用“活动带来全部增长”“爆款应继续加库存”“渠道质量差”“物流导致退货”等未被对照或订单级证据支持的判断。

## 图表优先级

1. 金额、订单和用户趋势与历史基线；
2. 分母明确的转化漏斗；
3. 品类/SKU 规模 × 毛利/库存效率散点；
4. cohort 复购/留存热力图；
5. 活动成本—归因收入瀑布或处理/对照效应图；
6. 退款原因帕累托与 SKU/物流分面；
7. 库存、缺货和销售成本的时间序列。

每张图注明金额口径、实体、窗口、分母、观察窗、归因和排除规则；条件不足时只画描述性图表。

## 输出与降级

分析计划至少输出：`business_decision`、`metric_dictionary`、`grain`、`event_time_policy`、`time_window`、`baseline`、`attribution_window`、`evidence_contract`、`selected_methods`、`selected_charts`、`missing_data` 和 `max_claim_level`。

- 没有订单/用户 ID：只做金额、订单量和 SKU 汇总，不做用户漏斗、复购或跨表关联；
- 没有支付/退款状态：不称 GMV 为实收，不算净销售额；
- 没有分子分母：不算转化、复购、退货或 ROI；
- 没有商品成本：不算毛利；没有库存快照：不算周转或缺货；
- 没有事件时间：不做时序、履约时效和活动前后比较；
- 没有归因/对照：只报告模型归因或关联，不写增量因果；
- 观察窗未结束：排除不成熟 cohort，披露右删失；
- 分组无法对账：不做贡献瀑布，不把分组率平均。

**最低可分析标准**：至少有订单/交易实体、金额或数量字段和一个可用时间字段；这只能支持基础交易趋势，不能自动支持用户、利润或营销归因分析。
