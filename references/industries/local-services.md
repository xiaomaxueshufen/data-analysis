# 互联网本地生活与 O2O 行业分析模板

## 适用范围与识别信号

适用于外卖、即时零售（商超快送、药品、鲜花、生鲜）、跑腿、上门服务（家政、洗衣、维修）、打车 / 网约车 / 共享出行、共享单车 / 共享充电宝、社区团购（次日达）、家政与月嫂、医美与口腔、社区健身、宠物服务。建议至少同时出现以下两类信号：用户 ID、骑手 / 师傅 / 司机 ID、商家 ID、订单 ID（服务单 / 即时单）、地址 / 网格（geohash / AOI）、发起时间、履约时间、距离 / 时长、客单价 / 抽佣 / 配送费。

仅有订单总额而无用户、骑手、商家、网格去重的，不能算"O2O 分析"——只能算规模描述。

## 业务链路与统计对象

```text
用户：打开 → 定位 → 浏览商家 → 加购 → 下单 → 支付 → 等单 → 收货 / 上门 → 复购 / 沉默
骑手：派单 → 取单 → 配送 → 完成
商家：接单 → 出餐 → 配送完成
平台链路：下单 → 派单 → 接单 → 履约 → 结算 → 分账 → 售后
```

实体层级（必须明确）：
- 用户 ID（账号 / 设备）；
- 骑手 / 师傅 / 司机 ID；
- 商家 ID；
- 订单 ID（含子单 / 履约单 / 配送单 / 退款单）；
- 网格 ID（geohash / AOI / 商圈）；
- 时点事件（发起 / 接单 / 取餐 / 完成 / 取消）。

**O2O 的关键是"地理 × 时段 × 人 × 单"四元组**：同一时间不同网格的供需匹配，单量分布按地理加权。网格平均差 5 倍。

## KPI 词典与必要条件

| 指标 | 推荐定义 | 至少需要 | 禁止推断 |
|---|---|---|---|
| DAU / MAU | 期内活跃去重用户数 | 用户 ID、活跃事件 | 打开 ≠ 下单 |
| 单量 | 期内成功履约的订单数 | 订单 ID、状态、履约事件 | 未支付 / 取消订单混入 |
| 发起单量 / 完成单量 | 期内发起 / 完成订单 | 订单 ID、状态 | 发起与完成不可混算 |
| 履约时长 | 接单→完成时长 | 接单事件、完成事件 | 缺任一项不能算 |
| 配送时长 | 取餐→送达时长 | 取餐事件、送达事件 | 商家出餐慢不算配送时长 |
| 等单时长 | 下单→骑手到达时长 | 下单事件、骑手到达 | 商家响应慢不算等单时长 |
| 客单价 | 订单金额 / 订单数 | 订单 ID、金额 | 加购 ≠ 成交价 |
| 单均配送费 | 配送费 / 订单数 | 配送费、订单 ID | 满减、免运费 |
| Take Rate | 平台净收入 / GMV | 抽佣、GMV | 不含配送费 |
| 网格单量密度 | 网格订单数 / 网格面积 | 网格 ID、订单 ID | 网格粒度不统一 |
| 网格供需比 | 网格骑手数 / 网格单量 | 网格 ID、骑手 ID、订单 | 实时 vs 静态 |
| 骑手 DAU / 在线时长 | 期内活跃骑手 / 总在线时长 | 骑手 ID、在线事件 | 在线 ≠ 有效在线 |
| 骑手人均单量 | 总单量 / 骑手数 | 骑手 ID、订单 | 在线 / 离线不同 |
| 接单率 | 接单 / 派单 | 派单事件、接单事件 | 派单 ≠ 接单 |
| 接单时长 | 派单→接单时长 | 派单事件、接单事件 | 拒绝重派不算接单时长 |
| 取消率 | 取消订单 / 总订单 | 取消事件、订单 ID | 用户取消 ≠ 商家取消 ≠ 骑手取消 |
| 退款率 | 退款订单 / 完成订单 | 退款 ID、订单 ID | 跨期退款 |
| 差评率 | 差评 / 总评价 | 评价 ID、评分 | 低回复率评价不可比 |
| 商家上线率 | 期内在线商家 / 期初商家 | 商家 ID、在线事件 | "营业中"与"有效营业"不同 |
| 商家接单率 | 商家接单 / 商家订单 | 接单事件、订单 ID | 商家关闭时段 |
| 用户复购率 | 期内多次下单用户 / 总下单用户 | 用户 ID、订单数 | 跨期复购与窗口内复购混算 |
| 用户留存 N 日 | 第 N 日活跃 / 第 0 日新增 | 用户 ID、活跃、新增 | 跨端打通 |
| 履约准时率 | 准时订单 / 总订单 | 预计时长、实际时长 | 承诺时长与实际时长口径 |
| 投诉率 | 投诉事件 / 总订单 | 投诉 ID、订单 ID | 同一事件多次投诉计 1 |
| 网格客单价 | 网格订单金额 / 网格订单数 | 网格 ID、金额 | 不同网格不可加 |
| 时段单量 | 按时段分布的单量 | 订单 ID、时间戳 | 跨时区时区对齐 |
| 营销核销率 | 核销 / 发放 | 优惠券 ID、订单 | 触达 ≠ 领取 ≠ 核销 |

## 必须通过的数据门禁

1. **用户 / 骑手 / 商家去重**：账号 / 设备打通规则；不互通时分别披露；
2. **订单状态**：下单 / 支付 / 接单 / 配送 / 完成 / 取消 / 退款 状态必须明确；
3. **时区与时段**：按城市时区对齐；不能统一用同一时区；
4. **网格粒度**：geohash 长度、商圈划分版本切换前后不可合并；
5. **履约事件完整性**：发起 / 接单 / 取餐 / 送达 / 完成 缺任一项不可计算对应时长；
6. **取消 / 退款**：用户取消 / 商家取消 / 骑手取消 / 系统取消 必须分清；
7. **跨期退款**：本期订单 → 跨期退款必须反映到本期；
8. **配送费结构**：配送费 / 满减 / 优惠券 / 抽佣分清；
9. **骑手在线 vs 有效在线**：在线但未接单与有效在线不可比；
10. **商家营业时段**：营业时段与上线时段不同，跨时段不可比；
11. **天气 / 特殊事件**：雨雪、节日、营销大促必须标注；
12. **履约准时口径**：商家承诺时长与平台承诺时长不同；
13. **骑手调度规则**：派单 / 抢单 / 指派 不同规则下单量分布不同。

## 典型分析主题与流程

### 1. 用户漏斗

打开 → 定位 → 浏览 → 加购 → 下单 → 支付 → 等单 → 完成 → 复购。每步分子分母对齐。

### 2. 时段 × 网格供需

按时段 × 网格看单量、骑手数、供需比。**不要**只看总单量——同一时段不同网格供需差异巨大。供需失衡时段是运力调度优化点。

### 3. 履约时长与等单时长

按时段 / 网格 / 商家分层看等单时长、商家出餐时长、配送时长。**不要**只看总履约时长——配送时长与商家出餐时长是两个独立优化点。

### 4. 骑手效率

骑手 DAU / 在线时长 / 人均单量 / 接单率。**不要**只看单量——骑手效率 = 单量 / 在线时长，时长维度的差异比单量大。

### 5. 商家质量

商家上线率、接单率、出餐时长、差评率按商家 × 时段 × 网格分层。

### 6. 取消 / 退款 / 差评

按取消方（用户/商家/骑手/系统）分类看原因占比。**不要**只报"取消率"——不同原因对应不同优化路径。

### 7. 客单价与价格段分布

按网格 × 时段看客单价分布。**不要**用均值代替分位——网格长尾会让均值严重偏。

### 8. 营销核销

优惠券 / 满减 / 配送费补贴核销率。**不要**只看触达——核销率是真正的转化。

## 行业叙事语言

- "DAU 为 X（账号）/ Y（设备），未打通跨端"——必须双口径；
- "网格 A 高峰期供需比 0.6，建议运力调度"——必须挂网格粒度；
- "等单时长 11.6 分钟，其中商家出餐 7.3 分钟，配送 4.3 分钟"——必须拆分；
- "履约时长为 X，按承诺口径为 Y"——必须双口径；
- "骑手人均单量为 X，按在线时长调整后为 Y"；
- "取消率 X%，用户取消 2.1%，商家取消 1.2%，骑手取消 0.8%"——必须按方分类；
- "未打通跨端，账号去重 vs 设备去重"——必须双口径。

避免使用"DAU 高就是订单高""履约时长变长是骑手问题""差评是商家问题"等忽略供需结构、网格差异、原因归类的描述。

## 常见数据陷阱

1. **DAU ≠ 下单 DAU**：打开 DAU 与下单 DAU 数字差几个量级；
2. **跨时区**：跨地域用同一时区会让早高峰 / 晚高峰失真；
3. **网格粒度**：geohash 长度不同网格数差 10 倍以上；
4. **等单时长 vs 配送时长**：等单时长包含商家响应；商家出餐慢 ≠ 骑手慢；
5. **取消原因**：用户取消 / 商家取消 / 骑手取消 / 系统取消 必须分清；
6. **骑手在线 vs 有效在线**：在线但未接单与有效接单不可比；
7. **商家营业时段**：营业时段与上线时段不同，跨时段不可比；
8. **跨期退款**：本期订单 → 跨期退款必须反映到本期；
9. **配送费结构**：满减 / 免运费 / 优惠券必须分清；
10. **客单价长尾**：网格长尾会让均值严重偏，应报分位；
11. **天气 / 节假日**：雨雪、节日、营销大促必须标注；
12. **履约准时口径**：商家承诺时长与平台承诺时长不同；
13. **派单规则**：派单 / 抢单 / 指派 不同规则下单量分布不同；
14. **评价回复率**：低回复率评价样本不可比；
15. **骑手调度规则变更**：规则切换前后接单率不可比；
16. **网格与商圈版本**：版本切换前后不可合并。

## 输出与降级

分析计划至少输出：`business_decision`、`user_grain`、`rider_grain`、`merchant_grain`、`grid_policy`、`timezone_policy`、`status_window`、`evidence_contract`、`selected_methods`、`selected_charts`、`missing_data`、`max_claim_level`。

- 没有用户 ID：不计 ARPU/留存，只计订单数；
- 没有骑手 ID：不报骑手效率；
- 没有商家 ID：不报商家质量分层；
- 没有网格：所有网格指标降级为城市级；
- 没有履约事件：所有时长指标降级为"下单到完成时间"，不拆分；
- 没有取消分类：不报取消原因；
- 跨时区不对齐：按时区分面展示，不跨时区合并；
- 网格粒度不一致：按粒度分面，不跨粒度合并；
- 派单规则切换：分段报告，不合并趋势。

**最低可分析标准**：至少有用户 ID、订单 ID、订单状态、订单金额、发起时间；这只能支持订单数 / GMV / 简单漏斗，不支持网格供需 / 履约时长拆分 / 骑手效率。
