# 互联网双边平台与电商市场行业分析模板

## 适用范围与识别信号

适用于 C2C / B2C / B2B 电商市场、撮合型双边平台、二手交易、本地服务、撮合 SaaS（外卖、打车之外的版本）、SaaS 应用商店、应用市场。建议至少同时出现以下两类信号：买家 / 用户 ID、卖家 / 商户 ID、商品 / 服务 ID、订单 / 撮合 ID、店铺 / 商品评分、价格 / 优惠 / 抽佣、发货 / 收货 / 售后、纠纷 / 退款 / 评价。

仅有 GMV 与订单数而不带买家/卖家去重、品类/价格、佣金规则的，不能算"市场分析"——只能算规模描述。

## 业务链路与统计对象

```text
买家：浏览 → 加购/收藏 → 支付 → 收货 → 评价/复购
卖家：入驻 → 上架 → 成交 → 发货 → 结算 → 售后
撮合链路：买家下单 → 平台订单 → 卖家履约 → 平台结算 → 分账
```

实体层级（必须明确）：
- 买家 ID；
- 卖家 ID（店铺 / 商户）；
- 商品 / 服务 ID（SKU / SPU）；
- 订单 ID（含子订单 / 履约单 / 退款单）；
- 评价 ID；
- 平台 ID（区域 / 类目 / 频道）。

**双边市场的关键是双边留存 + 价格 / 抽佣 / 履约规则**——一个卖家上架 → 一个买家下单 → 平台抽佣 → 卖家结算。GMV 是撮合规模，不是平台收入；take rate（抽佣率）是平台收入的核心指标。

## KPI 词典与必要条件

| 指标 | 推荐定义 | 至少需要 | 禁止推断 |
|---|---|---|---|
| GMV | 期内成功订单的总成交金额（按口径） | 订单 ID、金额、状态 | 未支付/退款的订单计入 GMV |
| 真实 GMV | 扣除退款后的 GMV | 订单 ID、退款 ID、状态 | "GMV"与"真实 GMV"混用 |
| 下单人数 / 付款人数 | 期内下过单 / 付过款的去重买家 | 买家 ID、订单状态 | "加购"≠"下单" |
| 客单价 | 总订单金额 / 订单数 | 订单 ID、金额 | 跨客单价 + 单客单价混用 |
| 单买家 ARPU | 总金额 / 去重买家 | 买家 ID、金额 | 按订单计数会失真 |
| 单卖家 GMV | 总 GMV / 去重卖家 | 卖家 ID、金额 | 跨类目不分类目 |
| 成交转化率 | 付款订单 / 浏览会话 | 买家 ID、订单、会话 | 浏览口径未去重 |
| 漏斗各步 | 浏览→详情→加购→付款→收货 | 各步骤分子分母 | 步骤口径不一 |
| Take Rate | 平台净收入 / GMV | 平台抽佣、GMV | 不含履约/广告 |
| 平台净收入 | 抽佣 + 广告费 + 履约收费 | 收入分类、订单 ID | 不细分 |
| 退款率 | 退款订单 / 成交订单 | 退款 ID、订单 ID | 跨期退款与当期订单混算 |
| 纠纷率 | 纠纷订单 / 成交订单 | 纠纷 ID、订单 ID | 同一纠纷多次投诉计 1 |
| 差评率 | 差评 / 总评价 | 评价 ID、评分 | 低回复率的评价不可比 |
| 履约时长 | 发货→收货时长 | 发货事件、收货事件 | 缺任一项无法计算 |
| 上架数 | 期内上架的商品数 | 卖家 ID、SKU ID | 已下架 SKU 混入 |
| 动销率 | 期内有销售的 SKU / 在架 SKU | SKU ID、销售事件 | "上架"与"在架"混淆 |
| 卖家留存 | 期内仍活跃卖家 / 期初卖家 | 卖家 ID、活跃 | "上架"≠"成交" |
| 买家留存 | 期内有购买买家 / 期初买家 | 买家 ID、购买事件 | 复购率与留存混用 |
| 复购率 | 期内多次购买买家 / 总购买买家 | 买家 ID、订单数 | 跨期复购与窗口内复购混算 |
| 品类集中度 | Top 类目 GMV / 总 GMV | 类目 ID、GMV | 长尾未列出 |
| 价格段分布 | 客单价分位 | 订单金额 | 加购价格 ≠ 成交价 |
| 搜索 → 成交 | 搜索后成交 / 总搜索 | 搜索事件、订单 | 跨设备搜索未对齐 |
| 优惠券核销率 | 核销优惠券 / 发放优惠券 | 优惠券 ID、订单 | 发放数 ≠ 触达数 |
| 流量分发 | 平台推送 / 自然流量占比 | 流量来源、订单 | 来源不互斥 |

## 必须通过的数据门禁

1. **订单状态对齐**：下单 / 付款 / 发货 / 收货 / 退款 / 完结 状态必须明确；
2. **买家 / 卖家去重**：账号 / 设备打通规则；不互通时分别披露；
3. **金额口径**：订单金额、付款金额、确认收入金额、平台分成必须分清；
5. **类目口径**：类目树版本切换前后不可合并；
6. **时区与时点**：跨地域订单时区不一致会导致日活失真；
7. **退款与售后**：跨期退款必须反映到当期；
9. **评价真实性**：低回复率的评价样本不可比；
10. **SKU 与 SPU**：单品 SKU 与商品 SPU 不可互换；
11. **库存**：库存与销售同步，未同步时缺货订单污染转化率。

## 典型分析主题与流程

### 1. 撮合漏斗

从浏览 → 详情 → 加购 → 付款 → 收货 → 评价 每步分子分母对齐。每步都明确买家身份（账号/设备/未登录）。

### 2. 双边留存

卖家留存：当期仍活跃卖家 / 期初卖家。"活跃"需明确定义（上架/有曝光/有订单）。两类留存合并看供需匹配。

### 3. GMV 与 take rate

GMV 增长 vs 平台净收入增长。看 take rate 是否稳定，下降要查结构（客单价、品类、抽佣规则变化）。

### 4. 品类与价格段分布

按类目 × 价格段看 GMV 占比与动销率。Top 类目集中度过高提示长尾缺货/缺流量。

### 5. 履约与售后

退款率、纠纷率、履约时长、差评率按卖家 / 类目 / 区域分层。

### 6. 复购与买家分层

按首单日期 cohort 看复购曲线。**不要**用 RFM 标签预测"会复购"——RFM 不预测响应。

### 7. 卖家分层与流量分发

新卖家 vs 头部卖家流量分发；自然流量 vs 平台推送占比。

### 8. 优惠与营销核销

优惠券 / 满减 / 拼团核销率，按品类与卖家分层。

## 行业叙事语言

- "GMV 为 X，按真实 GMV（扣退款后）为 Y"——必须双口径；
- "Take rate 为 Y，平台净收入为 Z"——必须挂抽佣规则；
- "Top 5% 类目贡献 X% GMV"——必须看集中度；
- "复购率为 Y，按买家 cohort"——必须挂窗口；
- "卖家留存 N 日为 Y%，未成熟 cohort 不参与对比"；
- "退款率 Y%，跨期退款已纳入当期"；
- "未打通跨端，账号去重 vs 设备去重"——必须双口径。

避免使用"GMV 增长代表平台收入增长""头部卖家贡献高就是平台好""买家留存高就是产品力强"等忽略双边结构、价格段、抽佣的判断。

## 常见数据陷阱

1. **GMV ≠ 平台收入**：GMV 是成交规模；平台收入是抽佣 + 广告 + 履约收费；
2. **GMV 包含未付款**：未付款 / 取消订单混入 GMV 会失真；
3. **跨期退款**：本期订单 → 跨期退款，必须反映到本期；
4. **退款率与成交率**：跨期退款与当期订单混算会低估退款率；
5. **客单价与单买家 ARPU**：客单价按订单计，ARPU 按买家计，两者不可互换；
6. **类目口径切换**：类目树版本切换前后不可合并；
7. **品类集中度过高**：Top 类目 80%+ 时长尾缺货或缺流量，未看分布就报 GMV 结构会失真；
8. **SKU 与 SPU**：按 SKU 计算动销率与按 SPU 计算不同；
9. **搜索与成交**：跨设备搜索未对齐时"搜索→成交"路径断裂；
10. **优惠券核销 vs 触达**：触达 ≠ 领取 ≠ 核销，必须分别报；
11. **价格段长尾**：客单价分布长尾严重时均值被拉偏，应报分位；
12. **评价回复率**：低回复率的评价样本不可比；
13. **库存与销售脱钩**：缺货订单污染转化率分母；
14. **双边留存污染**：买家/卖家留存定义不同（活跃定义），混算会失真；
15. **卖家入驻 ≠ 卖家活跃**：新入驻卖家未上架、未成交不应进卖家留存分母；
16. **平台推送与自然流量**：来源标签不互斥，加和会失真。

## 图表优先级

1. 撮合漏斗分子分母对账；
2. GMV 与真实 GMV 时间序列；
3. Take rate 与平台净收入趋势；
4. 类目 × 价格段 GMV 集中度；
5. 卖家留存 × 买家留存 双边留存矩阵；
6. 复购 cohort 曲线；
7. 退款率 / 纠纷率 / 差评率 分层；
8. 履约时长分布；
9. 优惠券核销漏斗。

每张图必须挂买家/卖家去重口径、金额口径（GMV/真实GMV/平台收入）、订单状态、类目版本与证据链。

## 输出与降级

分析计划至少输出：`business_decision`、`buyer_grain`、`seller_grain`、`amount_caliber`、`category_version`、`policy_window`、`evidence_contract`、`selected_methods`、`selected_charts`、`missing_data`、`max_claim_level`。

- 没有买家 ID：不计 ARPU/留存，只计订单数；
- 没有卖家 ID：不报卖家留存与卖家分层；
- 没有订单 ID：不报 GMV，只报"下单事件数"；
- 没有退款 ID：不报真实 GMV 与退款率；
- 没有类目：所有品类指标降级为全量；
- 跨期口径不一致：分段报告；
- 没有 Take rate 规则：不报平台净收入；
- 双边去重未打通：所有跨端指标按"未打通"披露；
- 没有库存：缺货订单从转化率分母剔除。

**最低可分析标准**：至少有买家 ID、卖家 ID、订单 ID、订单金额、订单状态；这只能支持 GMV / 订单数 / 简单漏斗，不支持 take rate / 双边留存 / 真实 GMV。
