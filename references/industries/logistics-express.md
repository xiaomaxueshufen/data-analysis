# 物流快递行业参考模板

## 适用范围与识别信号

适用于数据中出现运单/包裹、揽收、分拨、干线、到达网点、派送、签收、拒收、退件、网点、线路、承诺时效或扫描节点等字段的场景。仅出现“订单量”或“配送”一个词不足以确认模板；应至少有一个物流节点字段和一个时间/区域/线路字段，最好有包裹全链路 ID。

模板的作用是帮助模型提出正确的核验问题，不是把字段名自动解释成行业事实。字段含义、事件发生时间和统计对象仍以用户口径与数据字典为准。

## 业务链路

```text
下单/生成运单
  → 揽收
  → 分拨/装车
  → 干线运输
  → 到达目的网点
  → 派送
  → 签收/妥投
  → 售后：拒收、退件、破损、丢件、客诉
```

节点不是天然漏斗：一次包裹可能多次扫描、改派或退回。只有当每个阶段使用同一包裹实体、事件时间可排序、重复扫描规则明确时，才把节点转化率称为漏斗；否则只报告节点覆盖和时效分布。

## KPI 词典与必要条件

| 指标 | 推荐定义 | 至少需要 | 禁止推断 |
|---|---|---|---|
| 件量/订单量 | 统计窗口内去重包裹/订单数 | 全链路 ID 或明确去重键、统计时间 | 用扫描次数代替包裹数 |
| 揽收及时率 | 在承诺揽收时限内完成揽收的包裹数 / 应揽收包裹数 | 下单/应揽收时间、实际揽收时间、时限口径 | 没有应揽收集合时不能算 |
| 分拨及时率 | 在规定时限内完成分拨的包裹数 / 应分拨包裹数 | 分拨事件时间、节点、时限 | 用“已分拨数量/总件量”冒充及时率 |
| 干线准点率 | 按线路和班次按计划发车/到达的班次或包裹数 / 应执行数 | 计划时间、实际时间、线路/班次 | 没有计划时间不能判定准点 |
| 到达网点及时率 | 在目标时间前到达目的网点的包裹数 / 应到达包裹数 | 目的网点、计划/承诺时间、到达事件 | 仅凭最后一条扫描不能算 |
| 首次派送成功率 | 首次派送即成功的包裹数 / 首次进入派送的包裹数 | 派送尝试序号、派送结果、包裹 ID | 多次派送后签收不能归为首次成功 |
| 签收率/妥投率 | 窗口内完成签收/妥投的包裹数 / 进入应签收集合 | 包裹 ID、签收状态、观察窗规则 | 观察窗未结束时不能与完整期比较 |
| 妥投时效 | 从约定起点到签收的时长，报告中位数、P90 等分位数 | 起点事件时间、签收时间、时区和异常值规则 | 只有日期不能精确计算小时级时效 |
| 承诺时效达成率 | 在承诺时间前签收的包裹数 / 有承诺时间且应完成的包裹数 | 承诺时间、签收时间、承诺版本 | 没有承诺时间不能算 SLA 达成 |
| 平均/中位妥投时长 | 每包裹妥投时长的均值/中位数 | 同一包裹的起点与签收事件 | 跨包裹拼接节点时间 |
| 破损率 | 破损包裹数 / 交付或理赔包裹数，需声明分母 | 破损判定、包裹 ID、分母集合 | 客诉数不能直接当破损数 |
| 丢件率 | 确认丢件包裹数 / 应交付包裹数 | 丢件状态、观察窗、分母规则 | 长时间未扫描不自动等于丢件 |
| 拒收率 | 拒收包裹数 / 送达尝试或应签收包裹数 | 拒收状态和分母定义 | 未妥投不能直接归为拒收 |
| 退件率 | 进入退件流程的包裹数 / 发出或应交付包裹数 | 退件事件、包裹 ID、窗口 | 取消订单不一定是物流退件 |
| 客诉率 | 物流客诉包裹数或工单数 / 包裹数或订单数 | 工单类型、去重规则、分母 | 工单量不能与包裹量直接比较 |
| 单票成本 | 物流相关成本 / 完成口径的包裹数 | 成本科目、归属窗口、包裹分母 | 没有成本字段不能推断 |
| 人均/车均处理量 | 处理包裹数 / 工作人数或投入车辆数 | 作业时长、人员/车辆投入、同一窗口 | 仅有件量不能推出产能效率 |
| 网点产能利用率 | 实际处理量 / 可用产能 | 产能上限、班次/工时、网点粒度 | 高件量不等于高利用率 |
| 干线装载率 | 实际装载量或体积 / 可用载重或容积 | 装载与容量字段、线路/班次 | 发车班次数不能代替装载率 |

## 必须通过的数据门禁

1. **事件时间门禁**：时效和 SLA 必须使用事件时间；创建、入库和报告日期不能互换。
2. **全链路 ID 门禁**：没有包裹/订单全链路 ID，不把不同表的节点按日期或网点强行拼接。
3. **承诺时间门禁**：没有承诺时点、服务产品或时限版本，不计算承诺达成率。
4. **重复扫描门禁**：同一节点多次扫描必须有首次、最后一次或有效事件规则；不能把扫描行数当包裹数。
5. **粒度门禁**：网点、线路、区域的贡献拆解只有在分子分母可加总且时间窗口一致时进行。
6. **观察窗门禁**：末端未成熟的包裹不能与已经完成观察窗的包裹直接比较；需要右删失说明或延长窗口。
7. **成本门禁**：成本必须有科目、归属规则和分母，不能用行业常识填单票成本。

## 典型分析主题与流程

### 1. 时效趋势与 SLA 达成

确认起点/终点、承诺时间、服务产品和观察窗；按日、区域、网点、线路计算件量、P50/P90 妥投时长和 SLA 达成率；先看整体趋势，再做可加总的区域/节点贡献；对末端未成熟件和异常件单独标记。没有承诺时间时降级为实际时效分布，不写 SLA 结论。

### 2. 节点损失与异常漏斗

用同一包裹 ID 重建节点状态，定义节点顺序和重复扫描规则；计算进入节点、及时完成、异常滞留和退回数量；区分“未发生”“尚未观察到”和“数据缺失”。不能把状态覆盖率当成自然转化率。

### 3. 区域/网点/线路贡献

先核对分组能否汇总到总量，再拆总时效或件量变化；同时报告规模、组内效率和结构变化，防止把小网点的最大降幅误判为整体主因。没有共同粒度分子分母时只列组间描述，不画贡献瀑布图。

### 4. 峰值与产能压力

将件量按小时/班次与可用人员、车辆、场地、装载容量对齐；比较峰值件量、积压量、处理时长和产能利用率；不要仅凭件量峰值断言产能不足。缺少容量或投入字段时，只能说出现业务量峰值。

### 5. 异常件、客诉与服务后果

按破损、丢件、拒收、退件、客诉类型建立互斥或可重叠规则，明确一件包裹多次工单如何去重；将异常件率与时效、区域和服务产品对齐；相关关系写成候选，不写成单一根因。

### 6. 成本与服务水平权衡

同一时间、区域和服务产品下对齐成本、件量和 SLA；先做成本分摊与单位定义，再看成本变化是否伴随服务变化；没有成本字段时输出成本数据需求和可研究的权衡设计，不推估金额。

## 行业叙事语言

- “时效在 X 日相对同星期基线偏离 Y 小时”；
- “偏离主要集中在某节点/线路，是否造成整体变化仍需可加总贡献验证”；
- “该字段与滞留量同步变化，是待验证机制，不是已确认根因”；
- “末端包裹观察窗尚未完成，因此当前 SLA 结果存在右删失”；
- “数据支持优先排查某节点，但不能仅凭聚合表判定责任网点”；
- “若补充计划时间、事件时间和全链路 ID，可进一步验证 SLA、节点损失和线路贡献”。

避免使用“爆仓”“运力不足”“网点失控”“人为漏扫”等未被字段或事件日志直接支持的判断。

## 图表优先级

1. 时效中位数/P90 与目标或承诺线；
2. 节点状态漏斗或滞留量堆叠，但仅在 ID 和状态规则合格时绘制；
3. 网点/线路件量与组内时效的贡献条形图；
4. 小时件量、积压和可用产能的双轴或分面图；
5. 异常件类型与客诉的可对账分布；
6. 成本—服务散点，只有成本和服务在同粒度可比时绘制。

每张图必须写明实体、时间窗口、分母、观察窗和排除规则；没有这些信息，图表降级为描述性展示或不绘制。

## 输出与降级

行业分析计划至少输出：`business_decision`、`metric_dictionary`、`event_time_policy`、`grain`、`evidence_contract`、`selected_methods`、`selected_charts`、`missing_data` 和 `max_claim_level`。

- 没有事件时间：不算时效，只做件量/状态描述；
- 没有承诺时间：不算 SLA 达成率；
- 没有全链路 ID：不跨表拼接节点，不做包裹级漏斗；
- 没有可加总分组：不做贡献度；
- 没有成本字段：不推断单票成本；
- 质量事故影响关键节点时：先报告数据质量，不解释业务原因。
