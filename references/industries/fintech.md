# 互联网金融行业分析模板

## 适用范围与识别信号

适用于借贷（现金贷 / 分期 / 抵押 / 助贷）、财富（基金 / 理财 / 数字银行 / 股票 / 衍生品）、支付（钱包 / 收单 / 转账 / 跨境）、保险（互联网保险）、征信、风控与 B 端金融科技。建议至少同时出现以下两类信号：用户 KYC / 实名 / 风险等级、合同 / 借据 / 标的 ID、产品（标的 / 基金 / 标的池）、计息 / 还款 / 派息 / 资金流转、风控决策（通过 / 拒绝 / 限额）、资金端与资产端。

仅有月度撮合 / 资金流而不带用户级借据、风险等级或违约事件的，不能算"金融分析"——只能描述规模趋势。

## 业务链路与统计对象

```text
获客 → 注册 → 实名 / KYC → 风险评级 / 限额 → 申请 / 出借 / 充值
                                     → 审核 → 放款 / 成交 / 起息
                                     → 还款 / 派息 / 兑付
                                     → 续借 / 复购 / 提现
风控链路：申请 → 规则评分 → 模型评分 → 人工审核 → 通过/拒绝 → 限额调整
```

实体层级（必须明确）：
- 用户（自然人 / 主体）；
- 合同（每笔借据 / 标的 / 保单）；
- 资金事件（还款 / 派息 / 充值 / 提现）；
- 风险事件（逾期 / 违约 / 欺诈）；
- 资产端（借款人的资产）；资金端（出借人的资金）。

风控与业务指标必须按实体层级去重。一个用户可有多份借据、一笔借据可分多期还款；所有衍生指标必须基于合同 ID 或资金事件 ID。

## KPI 词典与必要条件

| 指标 | 推荐定义 | 至少需要 | 禁止推断 |
|---|---|---|---|
| DAU / MAU | 期内活跃去重用户数 | 用户 ID、活跃事件、定义 | 登录或打开不算"活跃业务" |
| 实名率 / KYC 通过率 | 完成 KYC 用户 / 提交申请用户 | KYC 事件、KYC 等级、用户 ID | KYC 步骤通过率与最终通过率混算 |
| 转化率（注册→首借） | 首次成功放款用户 / 注册用户 | 用户 ID、首借事件 | "首借"与"首次申请"口径不同 |
| 风险评级分布 | 各等级用户/合同占比 | 评级时间、评级规则、合同 ID | 不同版本评级不可合并 |
| 通过率（风控） | 通过合同数 / 申请合同数 | 申请、风控决策、合同 ID | 复审拒绝率与首次拒绝率混算 |
| 放款额 | 期内成功放款金额 | 合同 ID、放款事件、金额 | 已放未提算作"放款" |
| 在贷余额 | 期末未结清本金 | 合同 ID、状态、剩余本金 | 包含已结清的合同 |
| 件均 / 笔均 | 总金额 / 合同数 | 合同 ID、金额 | 不同期限产品混算 |
| 期限结构 | 短期/中期/长期占比 | 合同期限、起息日 | 期限与产品版本不同步 |
| 利率 / IRR | 按内部收益率计算的实际年化 | 还款计划、IRR 模型 | 用单利代替 IRR |
| 资金成本 | 资金端付息率 / 拆借成本 | 资金端合同、付息事件 | 用名义成本代替 IRR |
| 净息差（NIM） | 资产端收益率 - 资金端成本率 | 资产/资金端金额与利息 | 不分层口径 |
| 逾期率（DPD N） | 逾期 ≥N 天余额 / 期末余额 | 还款事件、当前日期、合同 ID | 用"逾期金额 / 放款金额"代替 |
| 不良率（NPL） | 进入不良的余额 / 期末余额 | 资产五级分类规则 | 分类未到期的合同不可计入 |
| 坏账率（核销） | 期内核销金额 / 放款金额 | 核销事件、合同 ID | 核销延迟导致低估 |
| 核销回收率 | 期内回收 / 期内核销 | 回收事件、合同 ID | 跨期回收与当年核销混算 |
| M0 / M1 / M2+ 迁徙率 | 进入下一期的逾期余额 / 当前逾期余额 | DPD、合同 ID、时点 | 迁徙矩阵与当期逾期混算 |
| 复借率 | 期内再次成功放款用户 / 历史成功用户 | 用户 ID、合同事件 | 用户多次续借按 1 个计数 |
| 资金端留存 | 期内仍有余额的出借人 / 期初出借人 | 出借人 ID、余额快照 | 用"账户有余额"代替 |
| 资金端万份收益 | 万份收益 / 7 日年化 | 基金净值、份额 | 短期净值波动非独立 |
| 投诉率 | 投诉事件 / 期内交易事件 | 投诉事件、交易 ID | 同一事件重复投诉计为 1 |
| 反欺诈识别率 | 识别的欺诈事件 / 实际欺诈事件 | 欺诈标签、规则 | "高风险拒绝率"≠"识别率" |
| LTV（合同级） | 累计净收入 / 单合同 | 合同 ID、毛利规则 | 1/流失率补 LTV |

## 必须通过的数据门禁

1. **用户与合同去重**：跨设备、跨账号的去重必须明示，不能打全就披露口径；
2. **资金事件完整性**：所有资金流（充值 / 提现 / 还款 / 派息）必须按事件 ID 可对账；
3. **时点口径**：期末 vs 期初；逾期率分母必须用期末余额，不是放款额；
4. **逾期口径**：DPD 0/1/7/30/60/90 的口径必须显式；不同口径下数字差几个量级；
5. **核销政策**：核销触发时间与回写规则；不做核销的业务按"已逾期 ≥ 180 天"代用；
7. **资金端 vs 资产端**：两端不能混算净息差；中间业务（撮合）也要标注；
8. **IRR 口径**：用 IRR 不能与名义利率混算；
10. **风控模型版本**：评分模型 / 规则版本切换必须分段，否则所有通过率指标断点失真；
11. **合规报表口径**：上报口径（监管报送）必须与业务分析口径分开标注，不能互换。

## 典型分析主题与流程

### 1. 获客与漏斗

注册 → 实名 → 风险评估 → 申请 → 通过 → 放款 → 还款 的全漏斗，每步分子分母对齐。复借漏斗单独看（首次复借 vs N 次复借）。

### 2. 资产质量与迁徙

DPD 0/1/7/30/60/90 + M0→M1→M2 迁徙矩阵。**不要**只看单一期逾期率——迁徙速率才能预测 NPL。

### 3. 风险分层

按用户风险等级 / 合同金额 / 期限 / 产品 / 渠道分层看通过率、逾期率、回收率。每个分层至少 30 笔，未达不排名。

### 4. 资金端表现

出借人留存、复投率、平均持有期、净流入/出。财富端按产品（基金 / 理财 / 存款）单独看，不要合并。

### 5. 撮合与单位经济

撮合额 vs 资金端成本的覆盖、获客成本 vs LTV 的回收期。无 LTV 时不要报回收期。

### 6. 风控规则评估

拒绝率、误拒率（实际放款后逾期的合同中被拒绝的占比）、模型稳定性（PSI / KS）。**不要**只看通过率——通过率上升 5 个百分点可能伴随 20% 的逾期恶化。

### 7. 欺诈与黑产

反欺诈识别的事件、可疑交易占比、损失金额。识别率与拦截率分开报。

### 8. 合规与上报

监管报送口径下的指标与业务指标差异。报送数字不可作为业务 KPI 直接引用。

## 行业叙事语言

- "DPD 30+ 余额占比 X%，环比上升 Y 个百分点，迁徙率显示由 M0 进入 M1 的速率快于上月"；
- "通过率上升 Y 个百分点，但对应合同 90+ 逾期率上升 Z 个百分点"——必须双口径；
- "复借率为 X，按当前回收期 Y 个月"；
- "IRR 口径下资金成本 A，资产端收益 B，净息差 C"——必须挂 IRR；
- "IRR 名义利率 X% 不可直接与同业 Y% 对比，必须 IRR 化"；
- "模型稳定性 PSI > 0.25，评分分布漂移显著，建议暂停使用"；
- "NPL 口径按监管报送，未与业务分析口径对齐"。

避免使用"资产质量改善""复借率越高越好""通过率提升即效率提升"等忽略双口径和成本归属的描述。

## 常见数据陷阱

1. **逾期口径混淆**：DPD 1 vs DPD 30 vs DPD 90 不可互换，且 DPD 30 不等于 M0→M1 的迁徙；
2. **期末 vs 放款额分母**：用放款额作分母会严重低估不良率；
3. **核销延迟**：未核销的不良被低估，跨期对比失真；
4. **IRR 与 APR 混算**：IRR 是含手续费的内部收益率；APR 仅本金年化；
5. **用户与合同混淆**：复借率必须按用户去重，不能按合同计数；
6. **资金端与资产端混算**：撮合业务的"净息差"两边口径不一致；
7. **风控规则切换不标注**：模型版本切换前后通过率不可比；
8. **合规报送口径与业务口径混用**：监管报送数字是经过核销与计提的，与业务实时口径不一致；
9. **已结清合同污染**：在贷余额必须剔除已结清合同；
10. **跨期回收与当年核销混算**：核销回收率必须按合同生命周期，不是当年窗口；
11. **币种与汇率**：跨币种合并时未折算，或折算时点不一致。

## 图表优先级

1. 资产五级分类 + DPD 迁徙矩阵；
2. 通过率 × 逾期率双轴图（按人群/产品/渠道分层）；
3. 净息差与资金成本 vs 资产收益时间序列；
4. 资金端留存/净流入/平均持有期；
5. 复借 cohort 与回收期曲线；
6. 模型稳定性 PSI / KS 监控；
7. 反欺诈拦截与误拒监控。

每张图必须挂口径（DPD / IRR / 用户/合同）、窗口期与证据链。

## 输出与降级

分析计划至少输出：`business_decision`、`entity_grain`、`compliance_caliber`、`metric_dictionary`、`risk_policy_version`、`funding_asset_split`、`observation_window`、`evidence_contract`、`selected_methods`、`selected_charts`、`missing_data`、`max_claim_level`。

- 没有合同 ID：不计金额类指标，只计用户级比率；
- 没有 DPD 字段：不报逾期率，只报"到期未还率"（口径更粗）；
- 没有 IRR 模型：不报净息差，只报利差名义值；
- 没有风险评级版本：不与历史对比，仅报告当前分布；
- 没有反欺诈规则命中：所有反欺诈指标降级为"未识别事件数"；
- 跨期口径不一致：分段报告，不合并趋势；
- 报送与业务口径不一致：分别报告，禁止互换。

**最低可分析标准**：至少有用户 ID、合同 ID、合同金额、合同状态、起息日期；这只能支持规模描述、放款额趋势，不支持 NPL / 迁徙 / 净息差。
