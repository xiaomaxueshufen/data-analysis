# 互联网游戏行业分析模板

## 适用范围与识别信号

适用于手机游戏、客户端游戏、网页游戏、小游戏、H5、短剧互动、Steam 等平台型游戏、UGC/编辑器类、沙盒/MMO。建议至少同时出现以下两类信号：玩家 ID（设备 ID / 账号 ID）、登录事件、对局/关卡/任务事件、付费/充值事件、道具发放事件、版本/服务器/渠道 ID、公会/队伍/社交事件、活动/赛事 ID。

仅有下载量或简单 DAU 而无对局/付费明细的，不能算"游戏分析"——只能算"渠道规模"。

## 业务链路与统计对象

```text
渠道曝光 → 安装 → 注册 → 创角 → 教程 → 首次对局 → 首充 → 留存/复充 → 长留
                                                  → 流失 / 召回 / 流失付费
```

实体去重：
- 设备 ID（iOS IDFA / Android OAID / 自有账号）；
- 玩家 ID（账号体系）；
- 角色 ID（单账号多角色）；
- 充值订单 ID；
- 道具 ID（发放/消耗事件）。

**游戏是多实体**：玩家、角色、账号、订单、道具、虚拟币，要分清"按玩家去重"还是"按角色去重"。同一玩家可在 iOS、安卓、小游戏三个端出现，未打通时所有跨端指标都是过估。

## KPI 词典与必要条件

| 指标 | 推荐定义 | 至少需要 | 禁止推断 |
|---|---|---|---|
| DAU | 期内活跃去重玩家数（按账号或设备） | 玩家 ID、活跃事件、去重规则 | 登录不等于有效活跃 |
| WAU / MAU | 周 / 月活跃去重 | 玩家 ID、活跃事件 | 与 DAU 直接加和不可比 |
| DAU/MAU | 日活粘性指标 | DAU、MAU | "会话"DAU 与"启动"DAU 不可比 |
| 新增玩家 | 期内首次创角的去重玩家 | 玩家 ID、创角事件 | 首次登录 ≠ 首次创角 |
| 启动次数 / 人均启动 | 启动事件 / 活跃玩家 | 启动事件、玩家 ID | 后台启动计为有效 |
| 人均时长 | 总在线时长 / 活跃玩家 | 会话时长、玩家 ID | 后台时长污染 |
| 次日 / 7 日 / 30 日留存 | 第 N 日活跃 / 第 0 日新增 | 玩家 ID、活跃、创角 | 跨端打通与否 |
| LTV（玩家级） | 累计净收入 / 累计新增 | 玩家 ID、充值、毛利 | 1/流失率补 LTV |
| ARPPU | 充值 / 付费玩家 | 充值、付费玩家 | 把全部玩家当分母 |
| ARPU | 收入 / 活跃 | 收入、活跃玩家 | 充值流水 ≠ 确认收入 |
| 付费率 | 付费玩家 / 活跃玩家 | 付费标记、玩家 ID | 首次充值 ≠ 历史付费 |
| 客单价 | 充值金额 / 付费订单 | 订单 ID、金额 | 平均订单 ≠ 平均玩家 |
| 充值流水 | 期内充值总金额 | 订单 ID、金额 | 平台抽成未扣 |
| 渠道分成后净收入 | 流水 × (1 - 渠道抽成) | 抽成规则、订单 | iOS 30%、安卓 50% 等 |
| 关卡 / 副本完成率 | 完成关卡玩家 / 进入关卡玩家 | 关卡 ID、玩家 ID | 进入计为完成 |
| 通关率 | 全部关卡通关玩家 / 进入玩家 | 关卡进度 | 不区分难度 |
| 流失率 | 期内未活跃 / 期初活跃 | 玩家 ID、活跃、窗口 | 与留存互为补集 |
| 回流率 | 流失后再次活跃 / 历史流失 | 玩家 ID、流失标记 | "沉默"≠"流失" |
| 推广召回率 | 触达召回玩家中再次活跃的比例 | 召回触达、玩家 ID | 召回口径不一 |
| 渠道安装量 | 期内各渠道带来的新增 | 渠道 ID、设备 ID | 同一设备多渠道归因 |
| CPI | 渠道成本 / 新增玩家 | 成本、新增、渠道 | 媒体归因 vs 厂商归因 |
| 留存收益（次留 LTV） | 7 日累计充值 / 7 日新增 | 玩家 ID、充值、新增 | 未成熟 cohort 不可推 |
| 漏斗完成率 | 每一步骤分子分母对齐 | 阶段 ID、玩家 ID | 全步骤口径不同 |
| 付费转化率 | 首充玩家 / 新增 | 玩家 ID、订单 | "首充"口径 |

## 必须通过的数据门禁

1. **账号与设备打通**：跨端用户合并规则要披露；未打通时所有去重指标都是过估；
2. **活跃定义**：登录 / 进入游戏 / 在线时长 ≥ N 分钟 / 完成有效对局 —— 不同口径下 DAU 数字差几个量级；
3. **付费定义**：首次充值成功 vs 首次扣款成功 vs 首次到账 —— 退款、灰度、渠道代收未到账都会失真；
4. **订单状态**：充值状态（成功 / 退款 / 待结算 / 失败）必须明确；
5. **关卡进度**：以关卡 ID + 通过事件 + 时间戳为最小单元；缺失则漏斗不闭合；
6. **渠道归因**：iOS、安卓、小游戏、PC 各端归因口径不同；
7. **货币与汇率**：跨地区服合并时需折算，注明汇率时点；
8. **活动与版本**：开服、版本更新、节日活动必须分段；
9. **退款回写**：退款何时反映到当期收入；
10. **道具/虚拟币**：发放与消耗分开记录，禁止用单一"虚拟币"字段表示净额；
11. **公会/队伍**：群体指标不能与单玩家混算。

## 典型分析主题与流程

### 1. 漏斗：渠道→激活→创角→首充

每步分子分母对齐。新增玩家口径必须明确（首次创角而非首次启动），否则首充率会过估。

### 2. 留存曲线（按渠道/版本/服务器）

按新增 cohort 与时间窗口对齐。次日留存是"基本盘"，7 日是"产品力"，30 日是"商业化基础"。**不要**把"留存 N 日"当作"留存 N 日的所有玩家"，而是"在 N 日活跃 / N 日新增"——别把动态 DAU 当留存分母。

### 3. 付费漏斗与 ARPPU 分布

付费率 / ARPPU / 付费用户分布（Top 5% 玩家贡献多少）。游戏行业头部 1% 玩家常贡献 50%+ 收入，未看分布前不报 ARPPU。

### 4. LTV 与回收期

按渠道 / 版本 / 服务器 cohort 的 LTV 曲线。CPI 回收期小于 90 天通常作为基准，**不要**用 1/流失率补 LTV。

### 5. 流失与回流

流失定义必须明确（多少天不活跃算流失）。回流率要与"沉默用户"区分。

### 6. 活动效果

活动期 vs 活动前后窗口的活动率 / 充值 / 留存对比，**不要**直接给"活动带来 X 充值"——活动期玩家结构也变了。

### 7. 渠道质量与归因

按渠道看新增、次留、LTV、回收期。**不要**只看"安装量"决定渠道好坏，要看次留与 LTV。

### 8. 道具 / 数值 / 经济系统

发放、消耗、库存、产出。**不要**用单一"虚拟币余额"字段代替经济系统——必须按事件对齐。

## 行业叙事语言

- "按账号去重的 DAU 为 X，按设备去重为 Y，未打通跨端"——必须双口径；
- "次留 35%，7 日留存 18%，30 日留存 9%"——分周期，不合并；
- "ARPPU 为 X，付费玩家中 Top 5% 贡献 Y%"——必须看分布；
- "CPI 回收期为 X 天，按当前 LTV 曲线"——必须挂窗口；
- "活动期间日活上升 11.6%，充值上升 22%，但活动期玩家结构改变，不能直接归因"；
- "DAU 中启动 DAU 与对局 DAU 分别为 X、Y，按对局定义"；
- "未打通跨端，单端数据"。

避免使用"留存下降是产品问题""渠道 ROI 高""活动带来 X 收入"等无处理对照的判断。

## 常见数据陷阱

1. **登录 ≠ 活跃**：必须定义"有效活跃"（进入主场景/完成对局/登录后停留 ≥ N 分钟）；
2. **首次启动 ≠ 首次创角**：未创角的玩家不应进漏斗；
3. **充值 ≠ 收入**：抽成、退款、灰度未到账必须扣减；
4. **跨端打通**：同一玩家 iOS + 安卓 + 小游戏，未打通时所有去重指标都是过估；
5. **付费用户定义**：首次成功 vs 首次扣款 vs 首次到账，差几个百分点；
6. **渠道归因**：iOS 30% / 安卓 50% / 小游戏分成，必须抽成后算净收入；
7. **Top 头部污染**：游戏行业 Top 1% 玩家贡献大，ARPPU 不看分布会过估；
8. **次留分母**：动态 DAU 不是留存分母，分母应是新增 cohort；
9. **版本切换**：新版本上线前后的留存不可比，必须分段；
10. **活动期玩家结构**：活动期玩家结构改变，所有对比要注明"活动期玩家 vs 常规期玩家"；
11. **退款与刷量**：未成年人退款、第三方代充、刷量未识别都会污染数据；
12. **会话时长**：后台时长污染、心跳包持续触发会拉高估；
14. **关卡进度不闭合**：漏斗中某一步没有分母时不能强行补；
15. **公会/队伍**：群体行为不能算到单玩家头上。

## 图表优先级

1. DAU/MAU 时间序列（双口径：账号 vs 设备）；
2. 留存曲线 cohort 热力图；
4. 付费率 / ARPPU 分布（含 Top 5%/10% 集中度）；
5. 渠道 × 次留 / LTV 散点；
6. 活动期前后窗口对比（含玩家结构）；
7. 关卡漏斗分子分母对账；
8. 道具 / 虚拟币发放消耗经济系统图；
9. 流失 / 回流 cohort 曲线；
10. CPI 回收期与 LTV 趋势。

每张图必须挂去重口径（账号/设备）、活跃定义、付费定义、版本号、渠道 ID 与证据链。

## 输出与降级

分析计划至少输出：`business_decision`、`player_grain`、`active_definition`、`payment_definition`、`channel_policy`、`version_window`、`event_window`、`evidence_contract`、`selected_methods`、`selected_charts`、`missing_data`、`max_claim_level`。

- 没有玩家 ID：不计 DAU/留存，只计启动次数与对局数；
- 没有充值订单 ID：不报 ARPPU/付费率，只报"充值事件数"；
- 没有关卡 ID：不报漏斗，只报活跃分布；
- 没有跨端打通：所有跨端指标降级为单端；
- 没有退款回写：所有收入指标加"按当期未扣退款"注释；
- 没有经济系统事件：不报虚拟币 / 道具指标，只报"发放事件数"；
- 没有版本号：所有跨期对比标注"含版本切换"；
- 没有渠道 ID：不报 CPI / ROI。

**最低可分析标准**：至少有玩家 ID、登录事件、付费订单；这只能支持 DAU / 充值流水 / 简单留存描述，不支持 LTV / 经济系统 / 关卡漏斗。
