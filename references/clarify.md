# Grill-Me 反问协议（硬门禁）

当用户问题模糊时，**必须先反问、后分析**。追问不是可选项，也不是礼貌性确认；它是把模糊请求编译成可检验分析问题的必要步骤。反问的这一轮**不生成完整报告、不输出正式结论**。

## 触发条件（命中任意一条即进入 Grill-Me 模式）

1. 用户只说“帮我看看这个数据”“分析一下”“出个报告”，没有指明具体问题；
2. 决策对象不明确：复盘归档、系统整改、预算调整、策略上线、用户触达会导向不同的主指标和基线；
3. 主指标不明确，或数据中存在多个合理候选指标（如同时有量和率）；
4. 时间口径模糊：事件发生日还是完成日、分析区间、是否允许跨日转化未说明；
5. 比较基线模糊：同星期、前后窗口、目标值、对照组还是版本对照未说明；
6. 用户问“为什么/原因/下降/上升”，但没有指明哪个指标、哪个日期或哪个分组；
7. 多个文件之间的关系不明确（主表、维表、字典、补充证据）。

## 跳过条件（满足其一即可跳过反问）

- 用户明确说“直接分析”“别问了”“用默认假设”或等价表述；
- 决策对象、主指标、时间口径、比较基线四项都已明确且无歧义。

用户要求跳过时，把所有默认假设写入语义合同并在报告中披露；此后不再反复追问。

## Grill-Me 模式的输出规则

命中触发条件的那一轮，输出只允许包含三部分，**到此为止，停下等用户回答**：

1. 一段不超过 5 行的数据结构快照（可选，帮助用户理解你在问什么）；
2. 3–5 个尖锐问题，每个问题必须说明“为什么它会影响结论方向”；
3. 每个问题的默认假设，用户可以直接回复“都用默认”。

禁止行为：

- 禁止在同一轮里既反问又输出完整分析报告；
- 禁止问与结论方向无关的问题（文件大小、格式、编码这类能自己查的事）；
- 禁止一次问超过 5 个问题；
- 禁止问完不等回答就自行假设并继续。

## 通用优先级

1. **决策对象**：报告服务复盘归档、系统整改、预算调整、策略上线还是用户触达？
2. **主指标**：看绝对量、率、金额、利润、用户数还是增量？分子、分母和去重实体是什么？
3. **时间口径**：事件发生日、完成日还是归因日？允许跨日转化吗？
4. **比较基线**：同星期历史、前后窗口、目标值、自然流量、对照组还是没有基线？
5. **已知事件**：活动、发布、投放、规则、系统、埋点或口径变更的日期。

## 方法追加问题

| 方向 | 只在必要时追问 |
|---|---|
| 异动 | 关心尖峰、水平漂移还是趋势断点？哪些日期是已知事故或口径变更？ |
| 漏斗 | 各阶段是否同一实体和同一时间窗？分母是进入阶段的人还是全量用户？ |
| 指标体系 | 谁使用看板？当前目标是拉新、转化、利润、留存还是风险控制？ |
| AB 实验 | 分流单位是什么？实验起止日、预设主指标、最小可检测效应和护栏是什么？ |
| 因果 | 动作是什么、何时发生、覆盖谁？是否有未处理且可比的群体？ |
| 分层 | 分层是为了触达、定价、风控还是运营？动作容量和成本上限是多少？ |
| 贡献度 | 要拆到渠道、设备、地区、版本还是用户层？各维度是否可加总？ |
| 比率拆解 | 分子、分母分别是什么？关注组内效率、结构变化还是两者都要？ |

## 反问示例

> 我看了下数据结构：90 天、4 个渠道、双平台、双版本，包含完整的安装-活跃-漏斗-支付链路。在正式分析前，有 4 个问题会直接改变结论方向：
>
> 1. **这份报告要支持什么决定？** 是版本回滚决策、渠道预算调整，还是复盘归档？——不同决定对应的主指标完全不同。默认：版本是否需要回滚。
> 2. **主指标看哪个？** 支付转化率、支付金额、DAU，还是崩溃率？默认：加购→支付转化率。
> 3. **分析区间和基线怎么定？** 用 8/20 版本上线前后对比，还是同星期历史基线？默认：上线前后各 7 天 + 旧版本对照。
> 4. **8/28 的信息流支付为 0 和 8/14 的会话空值，是已知数据事故吗？** 这决定它们进排除区还是参与归因。默认：先按数据质量事故排除。
>
> 回复“都用默认”我就直接开始；或者只改不对的项。

## 追问轮数上限

最多 2 轮。第 2 轮后若仍有歧义，按已确认信息 + 默认假设继续分析，并在报告首屏披露所有未确认假设及其影响。
